# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Planning

**Every plan must include a plain-English explanation** of what will change — a short, jargon-free summary (in addition to any technical detail) describing what the user will see/experience. The user always wants this, for every plan.

## Performance (standing rule)

**Every time you code something new for this site, do it in a way that optimises smoothness of running and minimises CPU cost.** Smoothness and low CPU/GPU cost are a first-class requirement, not an afterthought — weigh them in every change. In practice that means: avoid per-frame work on scroll/rAF (cache offsets, guard against redundant DOM writes), don't add live `backdrop-filter`/`blur`/SVG-filter passes that re-rasterize each frame, promote to compositor layers (`translateZ(0)`/`will-change`) only where it removes repaints — and lazily, not page-wide, prefer `transform`/`opacity` animations over layout/paint-triggering properties, reserve correct image dimensions to avoid reflow, and downscale heavy assets. When a feature can't be made cheap, say so and propose the lightest version. (The notes throughout this file marked "perf" are examples of this principle already applied.)

## Project Overview

Single-file static landing page for the **KOVA** social/travel app. All HTML, CSS, and JS live in `index.html`. No build tools, no framework. External deps (both via CDN): Google Fonts and **Lenis** (smooth-scroll, `unpkg.com/lenis`).

The site is **full dark mode** (Gen Z / cinematic direction). The page is a **normal vertical flow of full-height sections** over photographic backgrounds. Each content section slightly overlaps the one above it (negative margin) and has an irregular **hand-drawn wave** along its top edge (SVG `clip-path`). `REDESIGN_SPEC.md` (untracked, in the project root) is the design source of truth for the look.

> The earlier sticky "card-stack" mechanic (8 stacked `.page-card`s dealt onto a deck) and the per-step iPhone mockups were **removed** in the Round 3 redesign. There is no `.card-stack`, no `.page-card`, no `.iphone*`, and no `updateCardStack` anymore.

## Development

**Preview locally:**
```
python -m http.server 8080
# then open http://localhost:8080
```
Use a server (not `file://`) because some browsers block local-file CDN requests on file:// origins.

**Taking screenshots for review:**
Playwright MCP is available — navigate to `http://localhost:<port>`, resize to 1440×900. Gotchas:
- IntersectionObserver won't fire under programmatic scroll jumps, so inject `.in-view` on `.reveal` / `.letter-reveal` / `.word-reveal` before screenshotting.
- `window.scrollTo` fights Lenis (Lenis reverts to its own target each frame). Use `window.lenis.scrollTo(y, {immediate:true})` to position reliably — `lenis` is exposed on `window` for exactly this.
- **Never** save a screenshot to a filename that collides with a tracked asset. Save dev screenshots to `.playwright-mcp/` or a throwaway name.
- **Note:** when working under the Opus model, do **not** use Playwright to verify outputs (per the user's global instruction). Verify by reading the file / manual browser check instead.

## Mobile (Round 24)

The site was desktop-first; Round 24 added a real mobile layer. **The load-bearing rule: every mobile change lives inside `@media (max-width: 768px)`, and the desktop-only rules live inside `@media (min-width: 769px)`. The two ranges cannot overlap, so mobile work can never reach desktop.** Three things exist outside a media query and are therefore `display:none` at base / guarded in JS:

- **`.nav-toggle`** — the hamburger button (base rule `display:none`; the mobile query sets `display:block`)
- **`.hero-mobile-stat`** and **`.hero-mobile-chip`** — the mobile-only hero stat + chip (same pattern)
- Two JS guards — `matchMedia('(max-width: 768px)')` in the hero sequence, and `isPhone()` in the road IIFE

**Navbar → hamburger (all three pages).** A `.nav-toggle` `<button>` holding three `<span>` bars sits after the Get KOVA link; `.nav-links` gained `id="nav-links"`. On mobile `.nav-links` becomes `position:absolute` — which **removes it from the grid flow**, letting the bar collapse to `grid-template-columns: 1fr auto auto` (logo | Get KOVA | toggle). The panel's open/close animates `opacity` + `translateY(-8px)` + `visibility` only. **On mobile the nav is frosted constantly** — the mobile query sets `.nav::before { opacity: 1 }`, overriding the scroll-driven `--nav-glass` fade (the JS still runs and still sets the variable; desktop keeps the fade-in-over-100px behaviour). The dropdown panel uses **the same glass** (`rgba(255,255,255,0.06)` + `backdrop-filter: blur(12px)`) rather than a solid fill — an earlier `rgba(13,17,23,0.94)` dark fill was dropped at Mehdi's request. The second live blur is affordable because the panel is `visibility:hidden` when closed, so it is only painted while the menu is open, and you aren't scrolling then. The bars morph to an ✕ via `.nav.menu-open` (top rotates 45°, bottom −45°, middle fades) — `transform`/`opacity` only. A small IIFE per page toggles `.menu-open` + `aria-expanded`, and closes on link tap, `Escape`, and resize past 768px. **Each page carries its own copy of all of this** (CSS, markup, JS) — keep them in sync.

**Hero on mobile.** `.hero-seq-wrap` switches to `flex-direction:column` with `transform:none` (dropping the desktop `translateX(28px)`), so the two descriptor words **stack**. Without this the row needs ~470px and gets silently clipped by `body{overflow-x:hidden}`. `.hero-seq-line` and `.hero-title` both drop to `clamp(2.3rem, 10vw, 3.5rem)` — **they must stay equal** or the sequence→headline swap jumps. In the JS, the **fixed-slot width reservation is skipped on mobile**: it exists only because the *row* layout re-centres when "for students" → "by students"; stacked in a column that can't happen, and its inline `width` would fight the layout. The desktop floating `.hero-stat`s and `.hero-chip` stay `display:none`. Standing in: **`.hero-mobile-stat` pinned top-left** (`top:11%; left:5%; rotate(-7deg)`) and **`.hero-mobile-chip` pinned bottom-right** (250px `road_chip1.png`, `bottom:7%; right:3%; rotate(4deg)`), tilted to match the desktop scatter band (desktop stats use −6/7/−4deg, chip 3deg). **Both are siblings of `.hero-content`, not children** — `.hero-content` is `position:relative` and only as tall as its text, so absolute corners inside it would not be the screen's corners. As absolutely-positioned children of `#hero` they're also out of its flex flow, so the centred content column is unaffected. Their vertical positions are chosen to clear that centred block on a ~700px viewport; if the headline ever grows, re-check the overlap. The green `.hl` marker also sits ~10px taller on mobile (the gradient's transparent run shortens from 20px to 10px). **These are separate elements, not the originals repositioned** — the originals carry inline `top`/`left`/`width` that beat stylesheet rules, and both are absolutely positioned against `.hero-content` (`position:relative`), so moving their markup would change what their percentages resolve against on desktop.

**`100vh` → `100svh`** on `#hero` and `.site-section` inside the mobile query. `svh` is the *small* viewport height, which ignores the collapsing URL bar — sections stop being taller than the screen and stop resizing mid-scroll. Browsers without `svh` ignore the declaration and keep `100vh`. `#faq` also gets `min-height: max(100svh, 900px)` — the mobile equivalent of its desktop 840px budget, so an opening answer never resizes the section (and the `.card-bg` sized off it) mid-transition.

**How it works — two bugs fixed.** (1) `.hiw-step--right .hiw-step-num` sets `left:auto; right:-24px`; the old mobile rule `.hiw-step-num { left:0 }` had **lower specificity and lost**, stranding "02" at the right edge while 01/03 moved left. (2) `.hiw-step` is `align-items:center`, which when stacked centres children *horizontally*, so the 78%-wide shot and the 320px-max text ended up different widths and their left edges didn't line up. Both are fixed by making `.hiw-step-num` **`position:static`** on mobile (so `left`/`right` stop applying at all, rather than out-specifying them) and giving the step `align-items:flex-start` with number, `.hiw-step-screen`/`.hiw-shot` and `.hiw-step-text` all at `width:100%; max-width:320px` — **one shared left edge**.

**Other mobile adjustments.** More than a ride scales down (shots `max-width:280px`, headings 1.25/1.5rem, gaps 40px). Testimonials get the missing `.testimonials-inner { padding:80px 20px }`, narrower cards (210–236px) and halved `--drop` — **still on the 6-card `nth-child` cycle** — plus `animation-duration: 120s` (from 55s).

**Marquee seam fix (mobile).** With `gap:24px`, 12 cards have only **11** gaps, so `translateX(-50%)` lands half a gap (12px) short of where card 7 begins — a visible jolt every loop. On mobile the spacing moves to `margin-right:20px` on `.testimonial-card` with `gap:0`, giving every card an identical width+margin unit so half the track is exactly 6 units (verified: 2908px total, 1454px both ways). **Desktop still has the 12px seam** — the same fix would work there, it just wasn't in scope. Mobile also sets `will-change:auto` on the track: at ~2900px wide and a phone's 3× DPR the forced composited layer is very large, and letting the browser manage it avoids missing-tile blanking.

**Footer on mobile.** `.footer-nav` is a 2-column grid with `justify-content:space-between`: Ambassadors / For Businesses / Manifesto stack in column 1, **Terms of Service and Privacy Policy stack in column 2, right-aligned** (`justify-self:end`) — placed explicitly by `nth-child` `grid-area`, so **the markup order of the five links is load-bearing**. `.footer-top` uses `align-items:stretch` (not `flex-start`) so `.footer-top-left` spans full width and the right column can reach the edge. Vertical rhythm is tightened throughout (`footer` padding `28px 20px 24px`, top/bottom padding 18px, gaps 16/14/10px, `.footer-link` `min-height:30px`). Touch targets (`.nav-btn`, `.nav-toggle`, `.faq-question`) keep `min-height:44px`; footer links sit at 30px, a deliberate trade for the tighter footer Mehdi asked for.

**Roads on mobile.** A second `ROADS_MOBILE` waypoint map widens the x-swing to roughly .06–.95 — the desktop fractions span only ~.28–.72, which on a narrow, tall section collapses the S-curve into a near-straight line. `build()` picks the set via `isPhone()`, and `scheduleBuild()` already reruns on resize, so rotating the phone re-selects with no extra code. Note `inst.wp` was replaced by `inst.id`, since the waypoints are now resolved per build rather than captured once at setup.

**Press-link arrow.** Now an **inline SVG** (`.hero-press-arrow`, 0.8em, `stroke:currentColor`), not a character. `↗` (U+2197) isn't in Inter, so every OS substituted a different fallback font — it first rendered as a colour emoji on phones (Round 24 added `&#xFE0E;` to force the text glyph), and that in turn rendered thin and elongated on iOS while Windows drew a different arrow entirely. **A character cannot be made identical across platforms when the webfont doesn't contain it** — the SVG is the fix. Don't go back to a glyph.

## Layout: site-sections, overlap & waves (core)

The content sections (`#how-it-works`, `#testimonials`, `#more-than-a-ride`, `#safety`, `#ambassador`, `#faq`, `#download`) all carry the class **`.site-section`**:
```css
.site-section { position: relative; min-height: 100vh; display:flex; align-items:center;
                justify-content:center; overflow:hidden; margin-top:-44px;
                box-shadow: 0 -14px 48px rgba(0,0,0,0.55); }
```
- **Overlap:** `margin-top:-44px` pulls each section up over the one above. A z-index ladder keeps later sections on top: how-it-works 10 → testimonials 20 → more-than-a-ride 30 → safety 40 → ambassador 50 → faq 60 → download 70 → footer 80 (footer's *effective* z-index is actually `10000` from its own base rule; the ladder value is documentation only).
- **Top drop-shadow:** `box-shadow: 0 -14px 48px rgba(0,0,0,0.55)` casts upward so each section reads as sliding over the one above. NOTE: every section also has a wave `clip-path`, which clips the box-shadow to the section box — so this shadow is largely cropped away and barely visible. If a visible seam-shadow is ever wanted, it needs a separate **unclipped** layer.
- **Waves:** a hidden `<svg>` (first child of `<body>`) defines 7 `clipPath`s with `clipPathUnits="objectBoundingBox"` — `#wave-how-it-works`, `#wave-testimonials`, `#wave-more`, `#wave-safety`, `#wave-ambassador`, `#wave-faq`, `#wave-download`. Each is an irregular hand-drawn curve along the top edge (y ≈ 0.01–0.04, no repeating pattern). Applied via `#<id> { clip-path: url(#wave-<id>); }`. Content wrappers carry `padding-top: 80px+` so content clears the wave.

**Background layers per section** (`.card-bg` z 0 → `.site-section::before` overlay z 1 → `.road-svg` z 2 → content z 4 via `.site-section > *:not(.card-bg):not(.card-bg-edge):not(.road-svg)`):
- `.card-bg` (`inset:-10%`, `background-size:cover`) and `.card-bg-edge` (same image, radial mask — a soft halo around the sharper center) get their **image + position + scale/rotate** set **per-ID** (the variation block). The backgrounds are now rendered **sharp** — the earlier per-section `blur()` on `.card-bg` and the `blur(22px)` on `.card-bg-edge` were removed. `.site-section::before` is the dark overlay tint, also per-ID.
- **Compositor isolation (perf):** `.road-svg` carries `transform:translateZ(0); backface-visibility:hidden`, and in the **road-bearing sections** (how-it-works, testimonials, more-than-a-ride, ambassador) `.card-bg` (via a `translateZ(0)` appended to its transform) and `.card-bg-edge` (grouped rule) are promoted to their own layers. This is what stops the road's per-frame repaint from re-rasterizing the heavy photo backgrounds + wave clip on every scroll frame (was the main in-section scroll stutter). Non-road sections (safety/faq/download) are left unpromoted (no per-frame child invalidation, so no need to spend the VRAM).

## Key Patterns

**Navbar** — `position: fixed`, **full-width and flush to the top** (`top:0; left:0; right:0; border-radius:0`), 3-column grid (logo / centered `.nav-links` / Get KOVA), `isolation:isolate`. The bar itself is `background:transparent; border:none`; the glass lives on a **`.nav::before`** layer (`inset:0; z-index:-1; background:rgba(255,255,255,0.06); backdrop-filter:blur(12px); opacity:var(--nav-glass,0)`) — so at the very top the nav is see-through and **fades into frosted glass over the first 100px of scroll** (`updateNavGlass()` sets `--nav-glass = min(scrollY/100, 1)`, folded into the `_uiRaf` scroll loop). The middle nav links were removed in Round 9 and **re-added in Round 13** — `.nav-links` now holds **three `.nav-btn`s**, **all `<a>` tags**: **Ambassadors** (an `<a>` to the **Notion ambassador signup**, `https://ridekova.notion.site/join?v=38a7fa18132180f1869c000cd7287201&source=copy_link`, `target="_blank" rel="noopener"`), **For Businesses** (an `<a href="businesses.html">`), and **Manifesto** (an `<a href="manifesto.html">`). Because all three are `<a>` tags, the base `.nav-btn` rule carries **`text-decoration:none`** (Round 13) so they aren't underlined. **None of the three auto-highlight on scroll anymore** — the Ambassadors link was changed from a `scrollToSection('ambassador')` button to this external `<a>` (it no longer scrolls to `#ambassador`); the two cross-page `<a>`s never had a `data-target`. So `.nav-btn[data-target]` is now an **empty set** and the scroll-spy JS (`refreshNavOffsets`/`updateNavActive`) runs over nothing, but is left intact for any future in-page link. Middle links (`.nav-btn`) are **Inter 400**, resting `rgba(255,255,255,0.55)`, easing to `#fff` on hover/`.active` over `0.4s` (no bold/weight jump — removed so section-to-section active changes are smooth). The logo keeps `filter: invert(1) hue-rotate(180deg)` permanently (white text, green wheel). To add another link: `<button class="nav-btn" data-target="SECTION_ID" onclick="scrollToSection('SECTION_ID')">Label</button>` (in-page) or `<a href="page.html" class="nav-btn">Label</a>` (cross-page) inside `.nav-links`. **Get KOVA** (`.nav-btn.primary`) is now an **`<a>`** that links **directly to the App Store** (`https://apps.apple.com/us/app/ridekova/id6757269118`, new tab) — it no longer scrolls to `#download`. It's styled as a **liquid-glass pill with a green-tinted rim + text** (see Buttons) — but because it's a **fixed** element, its backdrop uses a cheap `blur(3px)` (the `url(#container-glass)` SVG filter was **dropped here for perf**: on a fixed pill it re-runs the turbulence filter over the scrolling page every frame). Active state is set by `updateNavActive()` which compares scroll against each target's document-top, **cached** by `refreshNavOffsets()` (called on init, `load`, `resize`, and after each road rebuild — previously it was defined but never called, so the active highlight was stuck on the last link; that's fixed). The Get KOVA link has no `data-target`, so it never gets `.active`. `updateNavActive` + `updateNavGlass` run from the single merged `_uiRaf` scroll loop (which also calls `window._roadScroll`).

**Hero** — `#hero` (z-index 1; not a `.site-section`, no wave clip; itself `display:flex; align-items:center; justify-content:center; text-align:center`, so the `.hero-content` column is **center-aligned and content-width** — this centering is why the descriptor slot needs a reserved width, see below). `drive pic.jpg` background + dark overlay (`.hero-bg::before`, `rgba(0,0,0,0.35)`). (The faint **`.hero-bg::after` dot grid was removed** in Round 11.) `.hero-content` (`max-width:780px`) is nudged **`transform:translateY(calc(7vh - 24px))`** so it sits a touch above center. (Rounds 14–15 briefly made it a four-line "editorial stack" with scroll parallax — **reverted in Round 16**; there is no `.hero-stack*` markup/CSS or hero parallax IIFE anymore.)

**Hero headline — two-container WAAPI slide sequence (Round 17).** Inside `.hero-content`: a **`#hero-seq-wrap`** holding two descriptor lines (`#hl-top`, `#hl-bottom`, class `.hero-seq-line`) laid out as a **flex row** (`gap:1em`, nudged right via `transform:translateX(28px)` — the wrap only; the headline is unaffected), then the `<h1 class="hero-title" id="hero-headline" aria-label="Your world just got bigger." style="display:none">` revealed only at the end. The `SPRITE` const is **shared by all roads**. The old `.road-sheen` (white .04) and `.road-reveal` mask path are **gone** (perf — see below). `.road-base` carries `shape-rendering:optimizeSpeed` (AA off — invisible at ~7% effective white, but much cheaper to raster); the brush + centre dashes keep AA. (The `bg` const that read `--bright-green` is still unused dead code.)
- **Maskless reveal (perf rewrite)** — the road used to draw via an SVG `<mask>` whose reveal path's `strokeDashoffset` changed every scroll frame, which forced a **full-section-sized offscreen mask buffer to re-rasterize every frame** (the big in-section scroll stutter, worst in the tall sections). Now each stroke reveals **itself**: `.road-base` via its own `strokeDashoffset` (one big dash = `totalLen`); `.road-center` via a per-frame computed `stroke-dasharray` from `centerDash(len)` that draws the `20 on / 18 off` dashes up to the drawn length then hides the rest. Same look, no offscreen buffer.
- **Model** — rAF-lerp driven by scroll progress within the section. `build(inst)` turns the waypoints into a Catmull-Rom path, sets `viewBox = "0 0 W H"`, computes `totalLen`, sets the base dasharray/offset hidden, stores `inst.top = absTop(card)` + `inst.h = H`, fills a 601-point `cache` for cheap `pointAt()`, and computes **`inst.maxLen`** — the path length at which the road first crosses the section bottom (`y ≥ H`), or `totalLen` if it never does (e.g. testimonials).
- **Scroll driver** — `updateTargets()` (driven from the merged scroll rAF) paces the draw to the **section's own height**: `progress = clamp((scrollY - (top - vh/2)) / h, 0, 1)`, `targetLen = p * totalLen`. `p=0` when the top edge reaches the viewport middle, `p=1` when the bottom edge does. **For a viewport-height section this matches the old center-crossing formula**, so short sections (testimonials, ambassador) are unchanged; the **tall** sections (how-it-works, more-than-a-ride) reveal top→bottom in step with scroll instead of bursting mid-section. *Earlier dead-ends: a fixed one-viewport window drew the tall roads mid-section, and a "static fully-drawn" variant looked abrupt — the height-paced formula is the keeper.*
- **`tick()`** eases `drawnLen → targetLen` (`SMOOTH ≈ 0.14`); skips all DOM writes for roads whose `drawnLen` is unchanged (`_lastDrawn` guard). The path reveal is **capped at `maxLen`** (`revealLen = min(drawnLen, maxLen)`, guarded by `_lastReveal`) so once the **visible** road is fully drawn it stops re-rasterizing — the off-screen tail (cropped by `overflow:hidden` / covered by the next section's overlap) never draws, which kills the "topping-off" stutter at the bottom of tall roads. The **car** still travels the full path (it moves by `transform` — cheap, not rasterized per frame) and fades out at the very start and once it nears the end.
- **Rebuilds** — `scheduleBuild()` coalesces rebuilds into a single rAF (each rebuild is ~2,400 `getPointAtLength` reads). It runs on initial load, `resize`, `window` `load`, and **`document.fonts.ready`** (font swap changes text height → section height). It deliberately does **not** rebuild per `.app-shot` `load` anymore — the shots carry correct `width`/`height` (height reserved before load), so a lazy image arriving as you scroll a section in no longer changes geometry; the old per-image rebuild was a heavy long-task landing right at the scroll-in moment (a first-load stutter). After a rebuild it also calls `refreshNavOffsets()` + `updateNavActive()`.

Roads (and Lenis) are skipped entirely under `prefers-reduced-motion` (IIFE early-returns and CSS hides `.road-svg`).
